
## The CIA Triad: Confidentiality, Integrity, Availability

These are the three core principles that all information security is built around — often called the **CIA Triad**. Every security control NovaPay puts in place is ultimately protecting one (or more) of these three things.

---

## Confidentiality

**Definition:** Protecting information from unauthorized access — making sure only the people who *should* see certain data actually can.

### NovaPay Examples

1. **Stolen employee credentials** — When employee usernames and passwords appear in a leaked database, confidentiality has been broken. Login information that should only be known to the employee is now exposed to attackers.
2. **Keylogging** — A keylogger secretly captures passwords and sensitive keystrokes as an employee types them. This is a direct confidentiality violation — private information is being accessed by someone with no authorization to see it.

---

## Integrity

**Definition:** Ensuring information has not been improperly changed, tampered with, or corrupted — whether by accident or on purpose.

### NovaPay Examples

1. **The fake social media post** — This is really an attack on integrity of *information*, not a system. False claims about NovaPay's financial collapse corrupt the accuracy of what the public believes to be true about the company.
2. **The rogue USB device** — If the malware from the USB modifies system files, settings, or data on the infected computer, that's a direct integrity violation — the computer's original, trustworthy state has been altered without authorization.

---

## Availability

**Definition:** Making sure authorized users can access systems and information whenever they need to.

### NovaPay Examples

1. **USB malware causing a computer to behave strangely** — If the malware slows down, crashes, or locks the employee out of their own computer, that's an availability problem — the authorized user can no longer use the system they need.
2. **Compromised account login** — If the attacker who logged in changes the employee's password or locks them out after gaining access, the legitimate employee is now denied access to their own account — a clear availability failure.
